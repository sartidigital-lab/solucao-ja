# Plan 01-02: Criação de Schemas de Banco de Dados e Triggers de Perfil no Supabase

## Objective

Configurar o banco de dados PostgreSQL do Supabase localmente (e remotamente), habilitando extensões críticas (PostGIS, pg_trgm, unaccent) e estruturando o schema relacional principal com triggers para sincronização automática de perfis de usuário após o signup.

## Verification

### Automated Tests
- Executar `supabase db lint` ou comando equivalente para validar a sintaxe do SQL de migração.
- Executar `pnpm --filter database build` para certificar que os tipos TypeScript gerados compilam corretamente sem erros.

### Manual Verification
- Iniciar o banco local com `supabase start` e validar que todas as tabelas, funções e triggers foram criadas com sucesso visualizando no console ou executando queries locais.

## Success Criteria

1. As extensões PostgreSQL (PostGIS, pg_trgm, unaccent) estão habilitadas.
2. O schema relacional completo está configurado com regras estritas de integridade de chaves estrangeiras.
3. RLS está ativado em todas as tabelas críticas para isolamento seguro dos dados.
4. Triggers do Supabase criam automaticamente a entrada correspondente em `public.profiles` ao registrar um novo usuário.

## must_haves

- Extensão PostGIS habilitada e coluna de localização configurada como Point geográfico com índice GiST.
- RLS habilitado e configurado para todas as tabelas de dados de usuário.
- Geração automática de tipos TypeScript (`types.ts`) a partir do banco de dados do Supabase.
